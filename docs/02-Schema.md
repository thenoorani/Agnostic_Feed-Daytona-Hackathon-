# 02 - Schema

We need a lightweight relational database (like PostgreSQL or SQLite) to track the sites being monitored, the generated scripts, and the historical scrape runs to detect changes.

## 1. `sites` Table
Stores the target URLs and their current monitoring status.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | UUID (PK) | Unique identifier for the site |
| `url` | String | The target URL (e.g., `https://example.com`) |
| `name` | String | Human-readable name of the site |
| `active` | Boolean | Whether the site is actively being monitored |
| `created_at` | Timestamp | When the site was added |
| `updated_at` | Timestamp | Last time the record was modified |

## 2. `scripts` Table
Stores the LLM-generated code. Separating this allows for "self-healing" version control if a script breaks.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | UUID (PK) | Unique identifier for the script |
| `site_id` | UUID (FK) | References `sites.id` |
| `code` | Text | The raw Python/Node code generated by the LLM |
| `version` | Integer | Increments when the script is regenerated |
| `is_active`| Boolean | True if this is the current working script |
| `created_at` | Timestamp | When the script was generated |

## 3. `scrape_runs` Table
Logs every execution inside the Daytona sandbox. Used for debugging, state management, and change detection.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | UUID (PK) | Unique identifier for the run |
| `site_id` | UUID (FK) | References `sites.id` |
| `script_id`| UUID (FK) | References `scripts.id` |
| `status` | Enum | `SUCCESS`, `FAILED`, `TIMEOUT` |
| `extracted_title` | String | The title parsed during this run |
| `extracted_subtitle`| String | The subtitle parsed during this run |
| `screenshot_url` | String | S3/Cloud Storage link to the saved screenshot |
| `content_hash` | String | SHA-256 hash of the extracted text/image to detect changes |
| `error_log`| Text | Daytona execution error logs (if `FAILED`) |
| `created_at` | Timestamp | When the run occurred |

## 4. `feed_items` Table
Tracks what has actually been pushed to Are.Na to prevent duplicate posts.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | UUID (PK) | Unique identifier for the feed item |
| `site_id` | UUID (FK) | References `sites.id` |
| `run_id` | UUID (FK) | References `scrape_runs.id` |
| `arena_block_id` | String | The ID returned by the Are.Na API |
| `pushed_at`| Timestamp | When it was successfully published to the feed |
